# Spells Feature — Design (Phase 1)

**Date:** 2026-07-12
**Status:** Approved design, ready for implementation plan
**Author:** Aaron LaBeau (with Claude)

## Summary

Add a **Spells** feature to Cartyx that behaves like the existing wiki features
(Races, Rules, Notes): players can browse, search, and tag-filter spells; game
masters (GMs) can create, edit, and delete spells. Unlike other wiki entries,
spells carry a **structured data model** (level, school, casting time, range,
components, duration, damage modifiers, area of effect) so that later phases can
roll damage dice from a spell and draw its area of effect on the tabletop map.

The System Reference Document (**SRD 5.2.1**, CC-BY-4.0) spells are ingested into
a committed, structured JSON dataset and loaded into a campaign on demand.

This spec covers **Phase 1 only**. It designs the data model so that Phase 2
(dice rolling) and Phase 3 (map overlays) are purely additive — no data model
changes required for them.

### Phasing

- **Phase 1 (this spec):** Spells wiki — structured model, SRD 5.2.1 ingestion +
  generated data, in-app SRD importer + campaign-creation checkbox, GM CRUD +
  duplicate, player read-only view, level/school/tag filters, SRD licensing
  screen, tests.
- **Phase 2 (future):** Roll damage dice from a spell's `modifiers` using the
  existing dice roller. No model changes.
- **Phase 3 (future):** Draw a spell's `areaOfEffect` on the tabletop `spell-fx`
  map layer. No model changes.

## Decisions (locked)

1. **SRD source:** structured JSON, **generated by us** from the SRD 5.2.1
   CC-BY-4.0 source (no ready-made 5.2.1 JSON exists) and committed to the repo.
2. **Model scope:** full DNDBeyond parity — header fields plus first-class
   `modifiers`, `conditions`, and per-level `higherLevels` sub-lists, plus class
   availability.
3. **SRD editing:** SRD spells are **read-only**; the GM **duplicates** an SRD
   spell to create an editable homebrew copy (`source: 'srd' | 'homebrew'`).
4. **Campaign import:** a **"Load SRD data" checkbox** on campaign creation loads
   **all** current SRD content (spells + races + rules) into the new campaign via
   a new in-app importer. Default **on**.
5. **Licensing:** an **SRD Licensing** info screen under the inspector cog
   (Settings), visible to all users, showing the exact required attribution.

## Architecture approach

Spells extend the established **wiki-document pattern** (modeled on `Race`):
clone the Mongoose model, Zod schemas, server functions (with
`requireCampaignMember` + `isGM` gating and per-row `canEdit`), the client hook,
the six-component UI, tag/search, drag-to-tabletop, and the seed pipeline — but
the model gains a rich, typed, indexed field set instead of only `content`.

Rejected alternatives:

- A single freeform JSON blob field — loses queryability/indexing (can't filter
  by level/school/class) and weak validation; defeats "advanced search/filter".
- A standalone non-wiki subsystem — abandons reuse and the wiki-consistent UX
  requirement.

## Data model

### `app/server/db/models/Spell.ts`

Clone `Race.ts` (tag normalization hooks, `mongoose.models.Spell || model(...)`
guard, index guard for mongodb-memory-server). Base fields from Race:
`campaignId`, `createdBy`, `tags[]`, `createdAt`, `updatedAt`.

Additional fields:

| Field                | Type                                                                                                                                                                                               | Notes                                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `source`             | `'srd' \| 'homebrew'`                                                                                                                                                                              | drives read-only protection                                                                      |
| `name`               | `String` (required)                                                                                                                                                                                | replaces `title`                                                                                 |
| `description`        | `String` (required)                                                                                                                                                                                | rich text / markdown                                                                             |
| `imageUrl`           | `String?`                                                                                                                                                                                          | optional R2 image                                                                                |
| `level`              | `Number` 0–9                                                                                                                                                                                       | 0 = cantrip                                                                                      |
| `school`             | enum                                                                                                                                                                                               | Abjuration, Conjuration, Divination, Enchantment, Evocation, Illusion, Necromancy, Transmutation |
| `version`            | `String?`                                                                                                                                                                                          | e.g. homebrew variant label                                                                      |
| `castingTime`        | `{ value: Number, unit: 'action'\|'bonus'\|'reaction'\|'minute'\|'hour', reactionCondition?: String }`                                                                                             |                                                                                                  |
| `components`         | `{ verbal: Boolean, somatic: Boolean, material: Boolean, materialDescription?: String }`                                                                                                           |                                                                                                  |
| `range`              | `{ type: 'self'\|'touch'\|'ranged'\|'sight'\|'unlimited', distance?: Number }`                                                                                                                     | distance in feet                                                                                 |
| `duration`           | `{ type: 'instantaneous'\|'timed'\|'concentration'\|'until-dispelled'\|'special', value?: Number, unit?: 'round'\|'minute'\|'hour'\|'day', concentration: Boolean }`                               |                                                                                                  |
| `ritual`             | `Boolean`                                                                                                                                                                                          |                                                                                                  |
| `higherLevelScaling` | `{ enabled: Boolean, type?: 'spell-scale'\|'character-level' }`                                                                                                                                    |                                                                                                  |
| `classes`            | `[String]`                                                                                                                                                                                         | class/subclass availability                                                                      |
| `attackSave`         | `{ kind: 'attack'\|'save'\|'none', attackType?: 'melee'\|'ranged', saveAbility?: 'str'\|'dex'\|'con'\|'int'\|'wis'\|'cha', saveEffect?: String }`                                                  | → card "Attack/Save"                                                                             |
| `modifiers`          | `[{ id, type: 'damage'\|'healing'\|'bonus'\|'proficiency'\|'other', dice?: { count: Number, sides: Number }, fixedValue?: Number, damageType?: String, atHigherLevels?: String, notes?: String }]` | → card "Damage/Effect"; **feeds Phase 2 dice**                                                   |
| `conditions`         | `[{ id, action: 'applies'\|'removes'\|'suppresses', condition: String }]`                                                                                                                          |                                                                                                  |
| `higherLevels`       | `[{ id, level: Number, description: String }]`                                                                                                                                                     | per-level scaling, max 25                                                                        |
| `areaOfEffect`       | `{ shape: 'sphere'\|'cone'\|'cube'\|'line'\|'cylinder'\|'none', size?: Number, width?: Number }`                                                                                                   | **feeds Phase 3 map overlay**                                                                    |

**Indexes:** copy Race indexes (`campaignId`, `{campaignId, updatedAt:-1}`,
`createdBy`, `tags`, `{name:'text', description:'text'}`) and add
`{campaignId, level}` and `{campaignId, school}` for the new filters.

`modifiers` and `areaOfEffect` are deliberate forward-compat hooks: populated in
Phase 1 from the SRD data, consumed in Phases 2 and 3.

### `app/types/schemas/spells.ts` (Zod)

Mirror `races.ts`: `createSpellSchema`, `updateSpellSchema` (adds `id`),
`deleteSpellSchema`, `listSpellsSchema` (adds `search`, `tags`, plus `level?` and
`school?` filters), `getSpellSchema`, and a new `duplicateSpellSchema`
(`{ id, campaignId }`). These schemas are the single source of truth, imported by
both the server functions and the client hook.

### `app/types/spell.ts` (TS types)

`SpellData` (full, includes `description`) and `SpellListItem` (omits
`description`; the list endpoint uses `.select('-description')` for payload size).
Both include `source` and `canEdit: boolean`. `SpellListItem` also carries `level`
and `school` for list rendering/filtering.

## SRD 5.2.1 ingestion & generated data

### Attribution (exact, from SRD 5.2.1 page 1)

> This work includes material from the System Reference Document 5.2.1 ("SRD
> 5.2.1") by Wizards of the Coast LLC, available at
> https://www.dndbeyond.com/srd. The SRD 5.2.1 is licensed under the Creative
> Commons Attribution 4.0 International License, available at
> https://creativecommons.org/licenses/by/4.0/legalcode.

This attribution is stored once as a shared constant and surfaced in the SRD
Licensing screen and in a `LICENSE`/`ATTRIBUTION` note beside the generated data.

### Generation script

A one-time (re-runnable) generation script produces committed JSON data modules.
No off-the-shelf 5.2.1 JSON exists, so we generate structured JSON from the SRD
5.2.1 CC-BY source:

- **Spells:** extract from the SRD 5.2.1 CC-BY markdown mirror (linearized
  `### Spell Name` + stat table per spell — far more reliable to parse than the
  two-column PDF), spot-checked against `docs/srd/srd.pdf`. Map each spell to the
  `Spell` shape above (`source: 'srd'`). `classes[]` availability lives in
  separate per-class spell lists in 5.2.1, so the extractor performs a
  cross-reference pass. Output is manually QA'd before commit.
- **Races / Rules:** generate from the existing `docs/srd/races/*.md` and
  `docs/srd/rules/**/*.md` markdown (same content the Python seed uses today).

**Output (committed, bundled, deploy-safe):** `app/server/data/srd/spells.json`,
`app/server/data/srd/races.json`, `app/server/data/srd/rules.json`. These are
**imported** by the server (bundled into the build), because the Node server does
not read `docs/` at runtime and `docs/**` may not ship with the deployed
container. This is the single source of truth for both the in-app importer and
the Python dev-seed.

### In-app SRD importer

New server util `importSrdContent({ campaignId, gmId, session })` in
`app/server/functions/` (or `app/server/utils/`):

- Reads the bundled `spells.json` / `races.json` / `rules.json`.
- Bulk-inserts documents scoped to `campaignId`, `createdBy: gmId`, with
  `tags` including `'srd'`.
- **Spells** are inserted with `source: 'srd'` (read-only). **Races/Rules** are
  inserted editable, exactly as the current Python seed produces them.
- Runs inside the caller's Mongo transaction (`session`) so it commits atomically
  with campaign creation.

### `dev_seed.py`

Refactor `scripts/dev_seed.py` so its SRD loaders read the **same generated JSON**
(add `import_srd_spells` reading `spells.json`; point `import_srd_races` /
`import_srd_rules` at the generated JSON) — one source of truth, no drift.
Test/sample (`bulk_test_campaign`) campaigns receive the full SRD set.

## Server functions & permissions

### `app/server/functions/spells.ts`

Clone `races.ts`. Two serializers (`serializeSpell`, `serializeSpellListItem`)
convert Mongoose docs → plain JSON. Every handler calls `requireCampaignMember`
first.

- `createSpell` — GM-only (`if (!member.isGM) throw 'Forbidden'`). New spells are
  `source: 'homebrew'`. Registers tags via `ensureTagsFn`.
- `updateSpell` — GM-only **and** rejects when the target's `source === 'srd'`
  (SRD spells are immutable). Scoped filter `{ _id, campaignId }`.
- `deleteSpell` — GM-only **and** rejects `source === 'srd'`. Cleans cross-refs:
  add `'spell'` handling to `removeDocumentRefsFromScreens`, `pruneLoreLinks`,
  `pruneEventLinks` so spells are linkable like races.
- `duplicateSpell` — **GM-only**; deep-copies any spell (typically an SRD one) to
  a new `source: 'homebrew'` document owned by the GM, editable. Name may be
  suffixed (e.g. "(Copy)") to disambiguate.
- `listSpells` — any campaign member; supports `$text` search, tag `$all`
  filtering, and `level` / `school` equality filters; `.select('-description')`;
  returns rows with `canEdit`.
- `getSpell` — any campaign member; returns `canEdit`.

**`canEdit` = `member.isGM && spell.source === 'homebrew'`.** Players always
read-only. The client trusts server-computed `canEdit`; the server always
re-checks authorization on mutations (never trusts client `isGM`).

### Permission model (existing, reused)

`requireCampaignMember(campaignId)` returns `{ userId, sessionUserId, isGM }`
where `isGM = campaign.gameMasterId === userId || member.role === 'gm'`.

## Client data layer

`import('~/server/functions/spells')` inside each handler keeps Mongoose
server-only). Hooks:

- `useSpells(campaignId, filters?)` — list (filters: search, tags, level, school)
- `useSpell(id, campaignId)` — detail

  gmscreens where relevant).

Add a `spells` block to `app/utils/queryKeys.ts` mirroring `races`.

## UI

Follow the Races six-component layout under `app/components/wiki/spells/`.

- **`SpellsPanel`** — container. `campaignId` from route params, `isGM` from
  `useCampaign`. Renders `WikiCategoryHeader` + a filter bar + a `SpellCard` list.
  The filter bar extends the shared `WikiFilterBar` behavior with **level and
  school dropdowns** in addition to search + tag filter. `onCreateClick` passed
  only when `isGM`. Row click: `canEdit` → edit `SpellModal`, else read-only
  `SpellViewModal`.
- **`SpellCard`** — one list row (name, level/school badge, tags). Draggable with
  `dataTransfer application/x-cartyx-document = { collection: 'spell', documentId,
title }`.
- **`SpellWindow`** (presentation) — matches `docs/spells/dnd-beyond-spell-
display.png`: the eight-cell header grid (Level · Casting Time · Range/Area ·
  Components · Duration · School · Attack/Save · Damage/Effect), rich-text
  description (`ReactMarkdown` + `remarkGfm`), class chips, tag chips, optional
  image, and a source/attribution footer. Player-visible.
- **`SpellViewModal`** — read-only portal wrapping `SpellWindow` for players
  (`!canEdit`), Esc-to-close. Includes `ShowOnTabletopButton collection="spell"`.
- **`SpellModal`** (GM create/edit) — matches `docs/spells/dnd-beyond-spell-
custom1.png` and `-custom2.png`. Sections:
  - **Basic Information:** name, version, level, school, casting time (+ reaction
    condition), components (V/S/M toggles + material description), range
    (type + distance), duration (type + value + concentration), description
    (markdown editor).
  - **Additional Information:** ritual flag, higher-level scaling flag + type,
    class availability multi-select, attack/save.
  - **Modifiers** — add/remove rows (`{ type, dice, fixedValue, damageType,
atHigherLevels, notes }`).
  - **Conditions** — add/remove rows (`{ action, condition }`).
  - **At Higher Levels** — add/remove per-level rows (`{ level, description }`,
    max 25).
  - Footer: save + two-step delete confirm. Gated to `isGM`.
  - On an **SRD spell**, the modal shows a **Duplicate** action (creating an
    editable homebrew copy) instead of editable fields.
- **`SpellWindowWrapper`** — wrappers for embedding a spell as a GM-screen window
  (fetch by id, render `SpellWindow` with optional edit callback).

### Wiki registration — `app/components/wiki/WikiPanel.tsx`

Add `spells` to the `WikiCategoryId` union and `WIKI_CATEGORIES`
(`{ id: 'spells', label: 'Spells', icon: Sparkles }`, visible to all — not
`gmOnly`), and a render branch `selectedCategory === 'spells' ? <SpellsPanel /> :`.

## Campaign creation — "Load SRD data" checkbox

- **UI:** `app/routes/campaigns/new.tsx` is a five-step wizard. Add a
  `loadSrdData` boolean state (default **`true`**), render a checkbox in Step 4
  ("The Roster"), and surface it in the Review step.
- **Schema:** add `loadSrdData: z.boolean().optional().default(false)` to
  `campaignInputShape` (`app/types/schemas/campaigns.ts`) — covers create + update.
- **Hook:** add `loadSrdData?` to `CreateCampaignInput` and thread it through
  `useCreateCampaign`'s `mutationFn` into `createCampaignFn`.
- **Server:** in `createCampaign` (`app/server/functions/campaigns.ts`), inside
  the existing Mongo transaction that creates Session 0 + the GMScreen, call
  `importSrdContent({ campaignId: campaign._id, gmId: dbUser._id, session })` when
  `data.loadSrdData` is true.

## SRD Licensing screen (inspector cog)

- **Settings registry:** add `'srd-licensing'` to `SettingsCategoryId` and push
  `{ id: 'srd-licensing', label: 'SRD Licensing', icon: <scroll/book icon in
the Settings panel's existing icon convention>, gmOnly: false }` to
  `SETTINGS_CATEGORIES` in `app/components/mainview/SettingsPanel.tsx`
  (visible to all users).
- **Screen:** a new info modal (modeled on `GameSettingsModal`) rendered when
  `openCategory === 'srd-licensing'`. Content:
  - the exact SRD 5.2.1 legal/attribution text (shared constant),
  - a link to the CC-BY-4.0 license,
  - a link to the official SRD (`https://www.dndbeyond.com/srd`),
  - a **link to the PDF**: serve a copy of `srd.pdf` from the app's public/static
    assets so the link resolves in production (the source `docs/srd/srd.pdf` is
    not web-served).

## Phases 2 & 3 (designed-for, not built in this spec)

- **Phase 2 — dice from spell text:** the `SpellWindow` description dice and a
  "roll damage" affordance build a dice `pool` from `modifiers[].dice`, then call
  `rollDice({ pool, mode, modifier })` → `toParsedDiceRoll` → `requestDiceBroadcast`
  (the existing dice bridge). No model changes; the `modifiers` field already
  carries the structured dice.
- **Phase 3 — map overlay:** `areaOfEffect` (+ `range`) drive an AoE template on
  the tabletop `spell-fx` layer. This is net-new: `spell-fx` is currently a
  placeholder and no cone/sphere tool exists — only a straight-line ruler. It
  extends `useRulerTool` (feet-per-square calibration) and `MapDrawingLayer`
  (SVG shape rendering). No model changes; `areaOfEffect` already carries the
  shape + size.

## Testing

- **Server functions** (mongodb-memory-server, per the seed-testing rule): CRUD,
  `duplicateSpell`, **SRD read-only rejection** on update/delete, GM-vs-player
  gating, `canEdit` computation, `listSpells` search/tag/level/school filters.
- **Zod schemas:** validation of create/update/duplicate/list inputs.
- **SRD importer:** integration test against an ephemeral mongodb-memory-server
  verifying spells (source `srd`), races, and rules are inserted and scoped to the
  campaign.
- **Generation script:** a check that the generated `spells.json` conforms to the
  `Spell` shape (counts, required fields, valid enums) so regenerations don't
  silently break.
- **Gates:** `npm test`, `npm run typecheck`, `npm run lint` all clean (respecting
  the ~24-warning lint baseline). e2e confirms the Spells wiki tab renders.

## Out of scope (Phase 1)

- Rolling dice from spells (Phase 2).
- Drawing spells on the map (Phase 3).
- Importing SRD content into pre-existing campaigns (only new campaigns via the
  checkbox, plus the dev-seed for test campaigns).
- Spell images beyond an optional `imageUrl` field (no upload flow required).
- Character spellbooks / prepared-spell tracking.
